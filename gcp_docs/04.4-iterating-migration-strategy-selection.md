# Iterating the migration strategy selection (6 Rs / 7 Rs)

At this stage, we recommend that you iterate and evolve both your **Stage 1 Strategic Disposition (Gartner TIME + Redundancy)** rules and your **Stage 2 6 Rs / 7 Rs decision tree** (where the classic 6 Rs expand to **7 Rs** when **Relocate** to **Google Cloud VMware Engine** is tracked as a distinct path alongside **Rehost** to **Google Compute Engine**).

The [Determining the R type for migration and modernization](./02.4-prioritization-and-migration-strategy.md) section and the [6 Rs Decision Tree Guide](./6rs-decision-tree.md) introduced the baseline decision model. At this stage of portfolio analysis, revise the model by incorporating:

- **Lessons learned from the pilot migrations** (for example, actual containerization effort with **Migrate to Containers (M2C)**, database conversion effort with **Database Migration Assessment (DMA)** and **DMS**, or VM replication velocity with **Migrate to Virtual Machines (M2VM)**).
- **Complete baseline portfolio data**, including newly discovered application dependencies, shared databases, commercial licensing constraints (**Oracle**, **Microsoft Windows Server / SQL Server**, **SAP**), and non-x86 / mainframe footprints.
- **Refined business drivers and prioritization criteria**, ensuring that strategic workloads with high functional change velocity are directed toward cloud-native modernization (**Cloud Run**, **GKE Autopilot**, **AlloyDB for PostgreSQL**, **Cloud Spanner**) while stable, low-differentiation workloads are either **retained/tolerated in place**, **consolidated/retired**, or moved via low-effort **Rehost / Relocate / Replatform** paths.

Validate the updated decision tree against a representative sample of applications across different technology stacks, and verify that it produces the expected component-level strategy. Allocate a specific strategy and Google Cloud target pattern to **each application component** (front-end, application tier, database tier) and its associated infrastructure. Component-level strategy allocation is a critical input for estimating effort, staffing capacity, and skills needed, and for grouping workloads in [wave planning](./04.5-wave-planning.md).
